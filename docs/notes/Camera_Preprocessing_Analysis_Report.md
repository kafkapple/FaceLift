## 1. D3 3종 차이 및 D4 비교

### 1.1 데이터셋 버전 계보

```
┌─────────────────────────────────────────────────────────────────────────┐
│                       PREPROCESSING VERSION HIERARCHY                    │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                          │
│  DEPRECATED (Object-Centered Paradigm)                                   │
│  ──────────────────────────────────────                                  │
│  D0~D2: Per-view 2D centroid → 뷰 간 불일치 (Ghosting)                   │
│  D3: 3D Triangulation center → PP=256 강제 (버그)                        │
│  D4: D3 + 카메라 정규화 → PP=256 강제 (여전히 버그)                      │
│                                                                          │
│  ACTIVE (PP-Centered Paradigm)                                           │
│  ──────────────────────────────                                          │
│  D7: PP shift + fx_only scale                                            │
│  D7.1: PP shift + individual scale (★ RECOMMENDED)                       │
│  D7.2: PP shift + average scale                                          │
│  D8: PP shift + Homography (skew correction)                             │
│  D9: Native resolution (no transform)                                    │
│                                                                          │
└─────────────────────────────────────────────────────────────────────────┘
```

### 1.2 D3 3종 상세 비교

| 버전 | Center Method | PP 처리 | Normalization | Ray Error | 상태 |
|------|---------------|---------|---------------|-----------|------|
| **D3-1** | Triangulation | 실제 값 | ❌ | 0° (정확) | ⛔ 미정규화 |
| **D3-2** | Triangulation | 256 강제 | ❌ | ~5° | ⛔ PP 버그 |
| **D3-3** | Triangulation | 실제 값 | ✅ | 0° (정확) | ⚠️ 복잡 |

**D3의 핵심 아이디어**: 3D triangulation으로 cross-view consistent center 계산
- D0~D2의 per-view 2D centroid 문제 해결
- 하지만 PP=256 강제 버그로 ray error 발생

### 1.3 D3 vs D4 차이

| 항목 | D3 | D4 |
|------|-----|-----|
| Center | 3D Triangulation | 3D Triangulation |
| PP | 256 강제 (버그) | 256 강제 (버그) |
| fx | 원본 (~1600) | **549** (정규화) |
| translation | 원본 (~300mm) | **2.7** (정규화) |
| Pretrained 호환 | ❌ | ✅ |

**결론**: D4 = D3 + 카메라 정규화. 둘 다 PP=256 강제 버그 존재.

### 1.4 D4 → D7 진화 이유

```
D4 문제점:
- PP=256 강제 → 평균 37px 오차 → ~5° ray error
- Object-centered crop → 정보 손실 가능

D7 해결책:
- PP 중심으로 이미지 SHIFT (crop 대신)
- PP가 자연스럽게 (256, 256)에 위치
- Ray error 0°
```

## 2. 260122 Mask 분석 보고서 결과

### 2.1 보고서 제안 사항 및 해결 상태

| 순위 | 문제 | 제안 해결책 | 현재 상태 |
|------|------|-------------|-----------|
| **P0** | Mask Mode 불일치 (시각화 vs Loss) | `compute_mask_from_config()` 재사용 | ⏳ 미해결 |
| **P1** | Alpha Mask 배경 침범 | `alpha_mask_threshold: 0.7` | ✅ E_quick_alpha로 테스트 가능 |
| **P2** | 이중 카메라 정규화 | `target_camera_distance: 0` | ⏳ 확인 필요 |
| **P3** | bf16 NaN | `.float().clamp(1e-4)` | ✅ 수정됨 |
| **P4** | View 5 Elevation Outlier | 제외 실험 | ⏳ 미실행 |
| **P5** | Dataset Path 형식 | 절대 경로 사용 | ✅ 해결됨 |

### 2.2 핵심 발견 요약

1. **Alpha 포화 문제**: `mask_mode: none`, `alpha_loss: 0`으로 학습 시 rendered alpha가 ~0.9999 (전체 foreground)
2. **해결책**: `mask_mode: gt` 활성화하여 GT mask 영역에서만 L2 loss 계산
3. **독립적 설정**: `mask_mode`(L2 loss 영역)와 `alpha_loss`(alpha supervision)는 **독립적**

## 3. 카메라 파라미터 교정 과정 상세

### 3.1 D7.1 전처리 5단계

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    D7.1 PREPROCESSING PIPELINE                           │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                          │
│  Step 1: SCALE (fx → 549)                                               │
│  ─────────────────────────                                              │
│    scale_x = 549 / fx_orig                                              │
│    scale_y = 549 / fy_orig                                              │
│                                                                          │
│    Example (View 0):                                                     │
│    scale_x = 549 / 1632.3 = 0.3363                                      │
│    scale_y = 549 / 1639.3 = 0.3349                                      │
│                                                                          │
│  Step 2: COMPUTE SCALED PP                                              │
│  ─────────────────────────                                              │
│    scaled_cx = cx_orig × scale_x                                        │
│    scaled_cy = cy_orig × scale_y                                        │
│                                                                          │
│    Example (View 0):                                                     │
│    scaled_cx = 601.3 × 0.3363 = 202.3                                   │
│    scaled_cy = 491.2 × 0.3349 = 164.5                                   │
│                                                                          │
│  Step 3: COMPUTE SHIFT                                                  │
│  ─────────────────────────                                              │
│    shift_x = 256 - scaled_cx                                            │
│    shift_y = 256 - scaled_cy                                            │
│                                                                          │
│    Example (View 0):                                                     │
│    shift_x = 256 - 202.3 = +53.7                                        │
│    shift_y = 256 - 164.5 = +91.5                                        │
│                                                                          │
│  Step 4: APPLY AFFINE TRANSFORM                                         │
│  ─────────────────────────────                                          │
│    new_pixel = scale × old_pixel + shift                                │
│                                                                          │
│    Transform matrix:                                                     │
│    ┌           ┐   ┌                           ┐                        │
│    │ x_new │   │ scale_x    0     shift_x │   │ x_old │                │
│    │ y_new │ = │    0    scale_y  shift_y │ × │ y_old │                │
│    └       ┘   └                           ┘   └   1   ┘                │
│                                                                          │
│  Step 5: PADDING TO 512×512                                             │
│  ──────────────────────────                                             │
│    - 변환 후 이미지가 512×512보다 작으면 흰색(1.0)으로 패딩             │
│    - 원본 1152×1024 → scale 0.336 → ~387×343 → 512×512 패딩            │
│                                                                          │
│  Step 6: DISTANCE NORMALIZATION                                         │
│  ───────────────────────────────                                        │
│    t_new = t_orig × (2.7 / dist_orig)                                   │
│                                                                          │
│    Example (View 0):                                                     │
│    dist_orig = 246.1mm                                                  │
│    factor = 2.7 / 246.1 = 0.01097                                       │
│    t_new = t_orig × 0.01097                                             │
│                                                                          │
└─────────────────────────────────────────────────────────────────────────┘
```

### 3.2 View 0 완전 계산 예시

**원본 파라미터**:
```
fx = 1632.3, fy = 1639.3
cx = 601.3, cy = 491.2
distance = 246.1mm
t = (10.34, 66.41, 236.70)
```

**Step 1: Scale 계산**
```
scale_x = 549 / 1632.3 = 0.3363
scale_y = 549 / 1639.3 = 0.3349
```

**Step 2: Scaled PP**
```
scaled_cx = 601.3 × 0.3363 = 202.25
scaled_cy = 491.2 × 0.3349 = 164.51
```

**Step 3: Shift**
```
shift_x = 256 - 202.25 = +53.75
shift_y = 256 - 164.51 = +91.49
```

**Step 4: Affine Transform (이미지)**
```
Original pixel (601, 491) [PP 위치]
↓
New pixel: (601 × 0.3363 + 53.75, 491 × 0.3349 + 91.49)
         = (202.25 + 53.75, 164.51 + 91.49)
         = (256.0, 256.0) ✓
```

**Step 5: 512×512 패딩**
```
변환된 이미지 크기: 1152 × 0.3363 = 387, 1024 × 0.3349 = 343
→ 512×512 캔버스에 배치 (나머지는 흰색 패딩)
```

**Step 6: Distance 정규화**
```
factor = 2.7 / 246.1 = 0.01097
t_new = (10.34, 66.41, 236.70) × 0.01097
      = (0.1134, 0.7288, 2.5973)
dist_new = 2.7000 ✓
```

**핵심 발견**: 이것은 **고정 멀티카메라 셋업**입니다.

## 5. Extrinsic Translation 부호 해석

### 5.1 좌표계 이해

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    COORDINATE SYSTEM CONVENTION                          │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                          │
│  w2c (World-to-Camera) 변환:                                            │
│  ─────────────────────────────                                          │
│                                                                          │
│    ┌       ┐   ┌     ┐   ┌       ┐                                      │
│    │ X_cam │   │ R   │   │ X_world │                                    │
│    │ Y_cam │ = │     │ × │ Y_world │ + t                                │
│    │ Z_cam │   │     │   │ Z_world │                                    │
│    └       ┘   └     ┘   └         ┘                                    │
│                                                                          │
│  Translation t = 카메라 좌표계에서 본 월드 원점의 위치                    │
│                                                                          │
│  Camera Center C (월드 좌표계):                                          │
│  ───────────────────────────────                                        │
│    C = -R^T × t                                                         │
│                                                                          │
│    이것이 실제 카메라가 월드에서 어디에 있는지를 나타냄                   │
│                                                                          │
└─────────────────────────────────────────────────────────────────────────┘
```

### 5.2 Translation 부호 의미

**원본 데이터 Translation (카메라 좌표계)**:

| View | tx | ty | tz | 부호 |
|------|------|------|------|------|
| 0 | +10.34 | +66.41 | +236.70 | (+,+,+) |
| 1 | -32.41 | +49.67 | +410.19 | (-,+,+) |
| 2 | +45.99 | +65.00 | +354.84 | (+,+,+) |
| 3 | -70.51 | +57.87 | +327.55 | (-,+,+) |
| 4 | +57.16 | +60.50 | +307.23 | (+,+,+) |
| 5 | -64.82 | +50.92 | +294.39 | (-,+,+) |

**해석**:
- **tx 부호**: + (View 0,2,4) vs - (View 1,3,5)
  - tx > 0: 카메라가 원점의 **오른쪽**에서 봄
  - tx < 0: 카메라가 원점의 **왼쪽**에서 봄
  - → 카메라가 생쥐 주위에 번갈아 배치됨

- **ty 부호**: 모두 +
  - ty > 0: 카메라가 원점 **아래**에서 위를 올려다봄 (일반적)

- **tz 부호**: 모두 +
  - tz > 0: 카메라가 원점 **앞**에 위치 (광학축 방향이 원점을 향함)

### 5.3 부호가 다른 뷰의 이미지 관계

```
tx > 0 (View 0, 2, 4):          tx < 0 (View 1, 3, 5):
카메라가 오른쪽에서 봄           카메라가 왼쪽에서 봄

     생쥐                            생쥐
       ●                               ●
      /|\                             /|\
     / | \                           / | \
        \                           /
    📷 (→ 봄)                    (← 봄) 📷
```

**결론**: tx 부호가 다르면 생쥐를 **반대 방향에서** 촬영
- View 0 (tx+) → 생쥐 오른쪽 측면
- View 1 (tx-) → 생쥐 왼쪽 측면
- 이것은 **정상적인** 멀티뷰 배치

### 5.4 정규화 후에도 부호 보존 확인

| View | Original t signs | D7_1 t signs | 일치 |
|------|------------------|--------------|------|
| 0 | (+,+,+) | (+,+,+) | ✅ |
| 1 | (-,+,+) | (-,+,+) | ✅ |
| 2 | (+,+,+) | (+,+,+) | ✅ |
| 3 | (-,+,+) | (-,+,+) | ✅ |
| 4 | (+,+,+) | (+,+,+) | ✅ |
| 5 | (-,+,+) | (-,+,+) | ✅ |

**전처리 후에도 translation 부호(방향)가 보존됨** ✅

## 7. -Rt 카메라 좌표 분석

### 7.1 카메라 위치 계산 공식

```
Camera Center in World = C = -R^T × t

여기서:
- R: 3×3 회전 행렬 (w2c의 회전 부분)
- t: 3×1 translation 벡터 (w2c의 이동 부분)
- R^T: R의 전치 (역회전)
```

### 7.4 카메라 배치 시각화

```
           Y (뒤)
           ^
           |
   cam4 ○  |      ○ cam1
   (-2,+1) |      (+2,+1)
           |
    cam2 ○ |
    (0,+3) |
───────────┼─────────────> X (오른쪽)
           |
   cam0 ○  |      ○ cam3
   (-2,-1) |      (+3,-0.5)
           |
           |  ○ cam5
           |  (+1,-2)
```

**관찰**:
- View 4, 5: ~90° 각도 차이 (질문에서 언급한 대로)
- 카메라들이 생쥐 주위에 불균등하게 배치됨
- 대략 60° 간격이 아닌 불규칙 배치

### 7.5 512×512 리사이즈 영향

**질문**: "512×512 리사이즈 어떻게 하셨는지?"

**답변**:
1. **Affine Transform**: scale + shift 적용
2. **Scale**: fx=549 목표로 ~0.336배 축소
3. **Shift**: PP가 (256, 256)에 오도록 이동
4. **Padding**: 나머지 영역은 흰색으로 채움
5. **카메라 파라미터**: fx=fy=549, cx=cy=256, dist=2.7로 정규화

**핵심**: 리사이즈는 단순 resize가 아니라 **기하학적으로 정확한 affine 변환**
